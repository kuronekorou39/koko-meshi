# 紹介動画のシナリオと撮り方

配布サイト・SNS 用の 30〜60秒の紹介動画。縦 9:16。

## 何を売るのか

機能を並べても伝わらないので、**他のアプリで我慢していることが要らなくなる**
という一点に絞る。食事記録アプリはたいてい、

- アカウントを作らされる
- 写真がどこかのサーバへ上がる
- 料理名やカロリーを手で入れる

このアプリはどれも要らない。**「撮るだけ」と「写真が外に出ない」が主役**で、
マップや振り返りはその結果として付いてくるもの、という順序で見せる。

機内モードのまま解析が走るカットを入れるのが一番効く。「端末内AI」と
文字で言うより、通信を切って動いて見せるほうが早い。

## 45秒版

| 秒 | 画 | テロップ |
|---|---|---|
| 0.0–3.0 | 実写。料理を前にスマホを構える手元 | その一枚が、記録になる |
| 3.0–7.5 | 撮影画面 → シャッター → 保存されて一覧へ戻る | 撮るだけ |
| 7.5–13.0 | 一覧のカードが「AIが解析中」→ 料理名とカロリーに変わる | 料理名も、カロリーも、AIが推定 |
| 13.0–19.0 | ステータスバーの**機内モード**を映してから、同じ解析が走る | 通信は切ったまま。<br>写真はどこにも送りません |
| 19.0–26.0 | タイムラインを上へスクロール。写真が次々流れる | 食べたものが、たまっていく |
| 26.0–34.0 | マップ。ピンが散らばった状態 → マイプレイスを開く | たまると、自分だけのグルメマップに |
| 34.0–41.0 | カレンダー → 振り返り画面のスコアとグラフ | 食べ方が、見えてくる |
| 41.0–46.0 | アプリアイコン + ロゴ | ココメシ<br>アカウント登録は、いりません |

46秒。テンポが速いと感じたら 19–26 と 34–41 を各1秒詰める。

## 30秒版（SNS用の短縮）

45秒版から 13–19（機内モード）と 34–41（振り返り）以外を削る、のではなく
**主役を落とさない**ように以下で組み直す。

| 秒 | 画 | テロップ |
|---|---|---|
| 0.0–2.5 | 撮影 → シャッター | 撮るだけで、食事が記録に |
| 2.5–8.0 | 解析中 → 料理名・カロリー | AIが料理名とカロリーを推定 |
| 8.0–14.0 | 機内モードのまま解析 | 通信は切ったまま。写真は外に出ません |
| 14.0–21.0 | タイムライン → マップ | 記録がたまると、グルメマップに |
| 21.0–27.0 | 振り返りのスコアとグラフ | 食べ方が、見えてくる |
| 27.0–30.0 | ロゴ | ココメシ／登録不要・無料 |

## ナレーションは入れない

テロップだけにする。SNS は音を切って見られることが多く、和のデザインに
合う声を用意するのも手間がかかる。**静かなBGM + テロップ**で成立する構成に
してある。BGM を付けるなら、商用利用と再配布の条件を必ず確認すること。

## 撮る前の準備

### データを仕込む

**空のアプリを撮っても何も伝わらない。** マップにピンが散り、カレンダーが
埋まり、タイムラインがスクロールできる状態を先に作る。最低でも

- 30〜50件の記録
- 2〜3ヶ月にまたがる日付
- 場所は5〜10箇所にばらける（マップが寂しくならない）
- 料理の種類もばらす（振り返りのグラフが単色にならない）

### 端末の見た目を整える

```bash
# ステータスバーを固定(時刻12:00・電池満タン・通知なし)
adb shell settings put global sysui_demo_allowed 1
adb shell am broadcast -a com.android.systemui.demo -e command clock -e hhmm 1200
adb shell am broadcast -a com.android.systemui.demo -e command battery -e level 100 -e plugged false
adb shell am broadcast -a com.android.systemui.demo -e command notifications -e visible false
adb shell am broadcast -a com.android.systemui.demo -e command network -e wifi show -e level 4

# タップした位置を出す(操作が伝わる)
adb shell settings put system show_touches 1
```

撮り終わったら戻す。

```bash
adb shell am broadcast -a com.android.systemui.demo -e command exit
adb shell settings put system show_touches 0
```

機内モードのカットでは `network` の broadcast を送らないこと。demo mode で
Wi-Fi を出したままだと、機内モードなのに電波が立っている画になる。

## 撮る

```bash
# 画面録画。1本あたり最大3分・音は入らない。Ctrl+C で停止
adb shell screenrecord --size 1080x1920 --bit-rate 12M /sdcard/cut01.mp4
adb pull /sdcard/cut01.mp4 promo/

# 静止画
adb exec-out screencap -p > promo/shot01.png
```

カットごとに別ファイルで録る。1本で通して撮ると、失敗したときに全部
撮り直しになる。

冒頭の実写カット（手元）だけは別のカメラで撮る。ここだけは画面録画では
撮れない。

### 撮影時の注意

- **AI解析は数十秒かかる。** 等倍で見せると間が持たないので、編集で 4〜8倍に
  早回しする。「解析中」の表示が出ていることが伝わればいい
- 解析を見せるカットは、**モデルのロードが済んだ2枚目以降**を撮る。初回は
  ロードに20秒ほど余分にかかる
- スクロールはゆっくり一定速度で。速いと何が写っているか読めない

## 組み立て

テロップはアプリと同じ書体（`assets/fonts/BIZUDGothic/BIZUDGothic-700.ttf`）を
使う。アプリの中と外で字面が変わらないほうがいい。

```bash
# 早回し + テロップ焼き込みの例
ffmpeg -i promo/cut03.mp4 -vf "setpts=0.15*PTS,\
drawtext=fontfile=assets/fonts/BIZUDGothic/BIZUDGothic-700.ttf:\
text='料理名も、カロリーも、AIが推定':fontcolor=white:fontsize=52:\
x=(w-tw)/2:y=h-260:box=1:boxcolor=black@0.45:boxborderw=24" \
  -an promo/out03.mp4
```

`setpts` は元の再生時間に対する倍率（0.15 なら約6.7倍速）。カットごとに
必要な尺へ合わせる。
