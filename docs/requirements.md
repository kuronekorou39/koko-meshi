# ココメシ (KokoMeshi) 要件定義書

## 1. プロダクト概要

「撮るだけ」で食事を全自動記録する食事ログ＆グルメマップアプリ。
料理の写真を撮るだけで、メニュー名・価格・カロリーを自動推定し、
高画質のままクラウドに保存。外食・自炊・出前すべての食事を対象とする。

### コアバリュー

1. **食事写真のクラウド管理** — スマホの容量を圧迫せず、いつでも閲覧・ダウンロード可能
2. **AI自動推定** — メニュー名・カロリー・金額をすべての食事で推定
3. **パーソナル・グルメマップ** — 外食分は地図上にマッピングして振り返り

### ターゲットユーザー

- 食事の写真をよく撮り、スマホ容量を圧迫している人
- 何をどこで食べたか振り返りたい人
- カロリーや食費を把握したい人

## 2. MVP スコープ

### MVP（フェーズ1）に含めるもの

- 料理写真の撮影 / ライブラリからの選択
- 食事種別の選択（外食 / 自炊 / 出前）
- 外食時: GPS + 時刻によるレストラン特定（候補リストから選択）
- 出前時: 店名の手動入力または検索
- AI による メニュー名・推定価格・推定カロリーの自動入力
- ユーザーによる手動修正
- 高画質オリジナル写真のクラウド保存（いつでも閲覧・ダウンロード）
- パーソナル・グルメマップ（外食分のみピン表示・フィルタリング）
- 食事記録一覧（全種別をタイムライン表示）
- 同一場所・同一時間帯の写真グルーピング（1回の食事 = 1記録）
- オフラインファースト設計（ローカルDB優先、クラウドはバックグラウンド同期）
- ログイン不要で全機能利用可能（ログイン後にクラウド同期が有効化）
- Google / Apple Sign-in による認証（任意タイミング）

### フェーズ2以降

- 月別の支出・統計管理
- フレンド / SNS機能（タイムライン、ピン共有）
- プライバシー設定（自宅秘匿、遅延公開、公開範囲制御）
- 課金機能（フリーミアム）

## 3. 技術スタック

| 領域 | 技術 | 選定理由 |
|---|---|---|
| モバイル | Flutter (Dart) | UI表現力が高く、ビジュアル重視のマップ表示に適する。1コードベースでiOS/Android対応 |
| バックエンド / DB / Auth | Supabase (Free) | PostgreSQL ベース。Auth（Google/Apple Sign-in）を標準サポート。無料枠で個人利用に十分 |
| ローカルDB | SQLite (sqflite / drift) | オフラインファーストの正データ。高速なローカルアクセス |
| 画像ストレージ | Cloudflare R2 | 10GB無料。読み出し（エグレス）無料。CDN統合で画像配信が高速 |
| 画像解析（AI） | Claude API (Vision) - Haiku 4.5 | 料理写真からメニュー名・推定価格・推定カロリーをJSON形式で返却。1枚あたり約0.5円、1-2秒 |
| 地図表示 | Google Maps SDK for Flutter | ユーザーに馴染みのある地図。Flutter SDKあり |
| 店舗特定 | Google Places API | GPS座標から周辺レストラン候補を取得。店舗データ量が圧倒的。月$200無料クレジット |

### スケールアップ計画

初期はB構成（Supabase Free + Cloudflare R2）で運用し、
ユーザー増加や機能拡張に伴い、Supabase Pro（$25/月、100GB Storage含む）へ移行可能。
性能差は個人利用ではほぼなし。Supabase Freeは7日間未使用でDB一時停止（自動復帰）する点のみ注意。

## 4. アーキテクチャ

### オフラインファースト設計

ローカルDB（SQLite）を正（source of truth）とし、クラウドはバックグラウンドで同期する。
ログインしなくても全機能が使える。ログイン後にクラウドバックアップが有効化される。

```
撮影 → ローカルDB + ローカルストレージに即保存（操作完了）
         │
         ├─ AI解析キュー（オンライン時にバックグラウンド実行）
         │    └─ 結果をローカルDBに書き戻し
         │
         └─ アップロードキュー（ログイン済み + オンライン時）
              └─ 高画質写真 → R2、メタデータ → Supabase
```

### キュー管理

- **AI解析キュー**: 写真ごとに pending / processing / completed / failed のステータス管理
- **アップロードキュー**: ログイン済みかつオンライン時に自動実行。リトライ機能付き
- どちらもアプリがバックグラウンドに入っても継続（OS制約の範囲内）

### 画面構成

```
起動 → ホーム画面（ログイン不要で即使える）

ホーム画面 (Home) ← ボトムナビゲーション
  ├─ タブ1: 食事記録一覧 (Timeline) ← デフォルト表示
  │    ├─ タイムライン形式、全食事種別表示
  │    └─ [大きなカメラボタン(FAB)] ← 1タップでカメラ起動
  ├─ タブ2: グルメマップ (Map)
  │    └─ 外食ピンを地図上に表示
  └─ タブ3: 設定 (Settings)
       ├─ ログイン / アカウント連携
       └─ 同期状況の確認

撮影フロー（FABから1タップ）
  ① カメラ起動 / ライブラリ選択
  ② 食事種別 + 店舗選択（外食時）
  ③ 保存 → ローカルDBに即保存、完了

食事記録詳細画面 (Detail)
  └─ 写真一覧、AI推定結果（解析中/完了）、手動編集、ダウンロード
```

### ログイン促進タイミング

- 初回起動時にスキップ可能な案内表示
- 設定画面から任意のタイミングで
- 一定枚数ローカルに溜まったら「クラウドにバックアップしませんか？」と提案

## 5. 画像管理設計

### 保存先の2層構造

| 保存先 | 用途 | タイミング |
|---|---|---|
| ローカルストレージ | 撮影直後の即時保存。オフラインでも利用可能 | 常時 |
| Cloudflare R2 | クラウドバックアップ。スマホ容量の解放 | ログイン済み + オンライン時 |

### 画像の3層構造

| 種類 | 用途 | サイズ目安 | 保存先 |
|---|---|---|---|
| オリジナル | 高画質のまま永久保存（スマホ写真の管理） | 3-8MB | Cloudflare R2 |
| AI解析用 | Claude APIに送信（一時的、保存不要） | 300-500KB | メモリ上で生成・破棄 |
| サムネイル | 一覧表示・マップのピン表示 | 20-50KB | Cloudflare R2 |

### グルーピングロジック

1回の食事で複数枚撮影することを想定し、以下の条件で自動グルーピング:

- GPS座標が半径50m以内
- 撮影時刻が2時間以内

→ 同一の「食事記録（MealLog）」としてまとめる

## 6. コア機能の詳細

### 6.1 写真撮影・取り込み

- カメラで撮影、またはフォトライブラリから選択（複数選択可）
- EXIF情報からGPS座標・撮影日時を取得
- 食事種別を選択: 外食 / 自炊 / 出前
- ローカルDB + ローカルストレージに即保存（ユーザー操作完了）
- AI解析・クラウドアップロードはキューに追加しバックグラウンドで処理

### 6.2 店舗特定（外食・出前時）

- **外食**: GPS座標を元に Google Places API (Nearby Search) で周辺飲食店の候補を取得
  - 候補リストをユーザーに提示し、選択してもらう
  - 商業ビル等で候補が多い場合に対応するため、リスト形式での選択を基本とする
  - GPS情報がない場合 → 手動で店舗を検索・選択するフォールバックUI
- **出前**: 店名を手動入力、またはPlaces APIで検索して選択
- **自炊**: 店舗紐付けなし
- 店舗情報（店名、住所、ジャンル）はローカルDB + Supabaseに保存

### 6.3 AI画像解析（非同期バックグラウンド処理）

撮影時にはAI解析を待たせず、キューでバックグラウンド処理する。

**バックグラウンド処理:**
1. AI解析キューから写真を取得（オンライン時）
2. 写真をリサイズ（1080px以下）して Claude API (Vision) に送信
3. プロンプトで以下をJSON形式で返却させる:
   - メニュー名（日本語）
   - 推定価格（円）
   - 推定カロリー（kcal）
   - 料理ジャンル（ラーメン、寿司、カフェ等）
4. 結果をローカルDBに書き戻し

**閲覧時:**
- 推定値であることをUIに明示
- ユーザーが手動で修正可能
- 解析未完了の記録は「解析中」と表示

### 6.4 パーソナル・グルメマップ

- Google Maps上に、外食の食事記録をピンとして表示
- 自炊・出前はマップには表示しない（一覧でのみ閲覧）
- ピンのアイコンは料理写真のサムネイル（ビジュアル重視）
- ピンタップで詳細表示（写真一覧、メニュー、価格、日時）
- フィルタリング機能:
  - 日付範囲
  - 価格帯
  - 料理ジャンル
  - フリーテキスト検索

### 6.5 食事記録一覧

- タイムライン形式で全食事記録（外食・自炊・出前）を時系列表示
- 各記録: 日付、食事種別、店名（あれば）、写真サムネイル、合計金額
- マップ表示との切り替え

### 6.6 写真の閲覧・ダウンロード

- クラウドに保存した高画質オリジナル写真をアプリ内で閲覧
- 任意の写真をオリジナル画質でスマホにダウンロード（保存し直し）可能

## 7. データモデル（概要）

### users
- id, email, display_name, avatar_url, created_at

### meal_logs（食事記録）
- id, user_id (nullable), meal_type (eating_out / home_cooking / delivery), restaurant_id (nullable), eaten_at, total_price, note, sync_status, created_at

### meal_photos（写真）
- id, meal_log_id, local_path, original_url (nullable), thumbnail_url (nullable), ai_status (pending / processing / completed / failed), ai_menu_name, ai_estimated_price, ai_estimated_calories, ai_cuisine_genre, user_corrected_name, user_corrected_price, user_corrected_calories, upload_status (pending / uploaded), shot_at, latitude, longitude, created_at

### restaurants（店舗）
- id, google_place_id, name, address, latitude, longitude, cuisine_genre, created_at

## 9. 非機能要件

- **オフラインファースト**: ログイン不要で全機能利用可能。撮影・閲覧・AI解析結果の確認すべてローカルで動作
- **手軽さ**: ホーム画面から1タップでカメラ起動（2ステップ以内）
- **バックグラウンド同期**: AI解析・クラウドアップロードはキュー管理でバックグラウンド実行
- **データ安全性**: ユーザーの写真・位置情報は本人のみアクセス可能（RLS）
- **対応OS**: iOS 15+ / Android 12+
